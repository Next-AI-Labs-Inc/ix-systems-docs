# API Registry

> A comprehensive registry system for the API codebase

## Overview

The API Registry is a central catalog of all functions in the backend, organized by context and annotated with status information. It allows for easy importing, exporting, and discovery of API functionality.

The registry is **automatically generated** by scanning the entire codebase, ensuring that it's always comprehensive and up-to-date. No need to manually add new functions - the system finds them automatically.

## Features

- **Complete Function Catalog**: Includes every function in the backend
- **Status Indicators**: Clear visual status of each function
  - ⚫ (Black): Default - no specific status assessment
  - 🟡 (Yellow): Legacy code - violates principles or old (typically files > 300 lines)
  - 🔵 (Blue): Latest code - recent code  
  - 🟢 (Green): Human verified - HUMANS ONLY define this
- **Functional Classification**:
  - ⚛️ (Atom): Simple atomic functions
  - 🧬 (Molecule): More complex functions composed of multiple operations
- **Context Organization**: Grouped by domain for easy discovery
- **Intent Descriptions**: One-sentence explanation of each function's purpose
- **Registry Integration**: Imports and aggregates other registry files
- **Auto-discovery**: Automatically finds and catalogs all exported functions

## Registry Files

The API Registry consists of the following files:

1. **api-registry.js** - The main registry file containing all functions organized by context.
2. **api-registry-index.js** - A simplified import interface for the registry.
3. **API_REGISTRY_README.md** - This documentation file.
4. **scripts/generate-api-registry.js** - The script that automatically generates the registry.
5. **update-registry.sh** - Shell script for updating the registry.

## Automated Generation

The registry is automatically generated by:

1. Scanning all JavaScript files in the codebase
2. Identifying exported functions using various patterns
3. Determining the appropriate context for each function
4. Assigning status and type indicators
5. Extracting intent descriptions from JSDoc comments or function names

To update the registry:

```bash
# Using npm script
npm run update-registry

# Or directly
./update-registry.sh
```

## Usage

### Import the Registry

```javascript
// Import entire registry
const apiRegistry = require('./api-registry');

// Import specific contexts
const { auth, subscription, user } = require('./api-registry');

// Import using simplified index
const apiRegistry = require('./api-registry-index');
```

### Using Registry Functions

```javascript
// Get a function by context and name
const createTask = apiRegistry.tasks.developerTaskController.createTask.func;
createTask({ title: 'New Task', description: 'Task details' });

// Or use the helper method
const createTask = apiRegistry.getFunction('tasks.developerTaskController.createTask');
createTask({ title: 'New Task', description: 'Task details' });

// Check function status
const status = apiRegistry.getStatus('tasks.developerTaskController.createTask');
console.log(`Function status: ${status}`); // 🔵

// Get function type (atomic or molecule)
const type = apiRegistry.getType('tasks.developerTaskController.createTask');
console.log(`Function type: ${type}`); // 🧬

// Get function intent
const intent = apiRegistry.getIntent('tasks.developerTaskController.createTask');
console.log(`Function intent: ${intent}`); // 'Create a new developer task with requirements'
```

### Available Contexts

The registry organizes functions into the following contexts:

- **auth**: Authentication and authorization
- **subscription**: Subscription management and billing
- **user**: User management and profiles
- **conversation**: Conversations and chat functionality
- **goals**: User goals and objectives
- **integration**: Third-party integrations
- **tasks**: Task and initiative management
- **utility**: Common utility functions
- **model**: Data models
- **route**: Route handlers
- **other**: Functions that don't fit in other categories

## Export Patterns Detected

The registry automatically detects the following export patterns:

1. **module.exports = function name() {...}**
   ```javascript
   module.exports = function getUserById(id) { ... }
   ```

2. **module.exports = { ... }**
   ```javascript
   module.exports = {
     getUserById,
     createUser,
     updateUser
   }
   ```

3. **exports.name = function() {...}**
   ```javascript
   exports.getUserById = function(id) { ... }
   ```

4. **const/let/var name = ... module.exports = name**
   ```javascript
   const userController = { ... }
   module.exports = userController
   ```

## Maintenance

When adding new functions to the API:

1. There's no need to manually add them to the registry
2. Use clear, descriptive function names
3. Add JSDoc comments with descriptive summaries
4. Run `npm run update-registry` to refresh the registry
