## Status Usage Guide

### How to Use Test Status Indicators

The status indicators in this document follow a specific workflow to track the progression of test failures through resolution:

1. **Initial Classification**

   - **⚫ TBD**: Use when a test failure is newly discovered and has not been analyzed
   - **🔴 Failing**: Default status for tests that are confirmed to be failing
   - **🔴 Critical**: Apply to tests that impact core business functions or critical user journeys

2. **Analysis & Investigation**

   - **🟡 Misconfigured**: Use when investigation reveals the test is failing due to setup issues rather than code defects
   - **🟠 Root Cause Analysis Complete**: Apply when the underlying cause has been identified and documented

3. **Resolution Progress**
   - **🟠 Partially Fixed**: Use when some aspects of the test have been fixed but it still fails in some scenarios
   - **🟢 Fixed**: Apply when the test passes consistently in the development/staging environment
   - **🔵 Deployed**: Final status when the fix has been verified in production

### Status Transition Flow

```
⚫ TBD → 🔴 Failing/Critical → 🟡 Misconfigured → 🟠 Root Cause Analysis → 🟠 Partially Fixed → 🟢 Fixed → 🔵 Deployed
```

Misconfigured tests may move directly to Fixed status if the configuration issue is resolved.

### Documentation Requirements

- When changing a test status to **🟠 Root Cause Analysis Complete**, create a detailed analysis document in the `/reports/` directory
- When marking a test as **🟢 Fixed**, include a reference to the PR or commit that contains the fix
- When updating to **🔵 Deployed**, add the deployment date and any relevant verification details
